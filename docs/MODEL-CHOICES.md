# Model choices

The spec left several "{insert best model}" placeholders. Here are the choices
and why, with a bias toward models that actually run **on the user's own device**
(a spec requirement for the web app's two stress models) and that are robust to
ship today.

## Web — video stress model → MediaPipe Face Landmarker

**Choice:** Google **MediaPipe Face Landmarker** (Tasks Vision), running in the
browser via WASM + WebGL. Implemented in
[`web/src/lib/videoModel.ts`](../web/src/lib/videoModel.ts).

- Emits **52 facial blendshape coefficients**, from which we read the tension
  cues the spec asks for: brow lowering (frustration), eye squint, mouth frown,
  and nose sneer / mouth stretch (cringe).
- Two lightweight CV heuristics on the frame cover the rest of the spec:
  **sweat** (forehead specular‑highlight ratio) and **eye‑redness** (R/(G+B) in
  the eye band).
- Runs fully client‑side; nothing leaves the computer. The model + WASM load
  from Google's CDN on first use.

Alternatives considered: `face-api.js` (7‑emotion CNN) is simpler but older and
gives a coarser signal; MediaPipe's blendshapes map more directly to the
spec's "frown / cringe / frustration" cues. Either could sit behind the same
`VideoModel` interface.

## Web — audio stress model → YAMNet (with a DSP default)

**Choice (recommended):** **YAMNet** (AudioSet MobileNet classifier) via
TensorFlow.js — it classifies "Sigh", "Breathing", "Gasp", "Shout", etc., which
are exactly the spec's cues (sighs, shallow breaths, sounds of anger).

**Shipped default:** a transparent Web‑Audio **DSP classifier** behind the same
[`AudioModel`](../web/src/lib/audioModel.ts) interface (RMS energy, spectral
brightness/flux, zero‑crossing rate, low‑band breathing energy). This keeps the
app working with **no large model download**; dropping in a YAMNet inference call
inside `sample()` requires no other code changes. Both emit a calmness value in
`[0, 1]`.

## Web — combined stress score

Average the two models' calmness and ×100 (see
[DATA-CONTRACT.md](./DATA-CONTRACT.md#stress-score-algorithm)). 100 = calm.

## iOS — sleep classifier → compact CNN on log‑mel spectrograms

**Choice:** a **compact CNN on log‑mel spectrograms** (MobileNetV2‑style
backbone), exported to **Core ML** and run on‑device. Each 10‑second audio window
→ log‑mel spectrogram → CNN → one of `{no event, Hypopnea, Obstructive Apnea,
Snoring}`. CNNs on mel‑spectrograms are the standard, well‑supported approach for
on‑device respiratory‑sound / apnea classification, and Core ML keeps it private
and battery‑friendly.

This model lives on the phone; the web app only **displays** the labels and the
sleep score it produced, read from Butterbase. The web side re‑derives the score
from the stored label offsets to verify agreement
([`computeSleepScore`](../web/src/shared/sleepScore.ts)).

## AI insights → Claude (`claude-opus-4-8`)

Personalized insights are generated by **Claude Opus 4.8** via the official
Anthropic SDK, called directly from the browser with the user's own API key
(stored only locally). See [`web/src/lib/claude.ts`](../web/src/lib/claude.ts).
